# Plan — Phase 3 Track 1: Feature Engineering → ML Engine → Ensemble

**Date:** 2026-07-30
**Design doc:** `docs/phase3_track1_design.md`
**Goal:** Boost explosive-stock detection accuracy (from ~12% toward 90%+) by replacing the weighted-sum signal with an ML ensemble, with graceful fallback when ML is not trained yet.

## Architecture (unchanged from design)

```
feature_pipeline.py ──> feature_store.db ──> ml_engine.py ──> predictive_scanner.py / signals.py
       │                     │                                    │
       └── 22 features       └── feature_vectors table            └── fallback to weighted sum
```

## Dependencies

```
feature_pipeline.py ──┬──> ml_engine.py ──> train_models.py ──> predictive_scanner.py
                      │         │                                  │
                      └── feature_store.db                         └──> signals.py
```

- Steps 1–3 (features + store + tests) are self-contained; can ship as a unit.
- Steps 4–6 (ml_engine + train + tests) depend on steps 1–3.
- Steps 7–9 (wiring + integration tests) depend on steps 4–6.
- Step 10 (run training) depends on everything.

## Steps

### Step 1 — `feature_pipeline.py` (NEW)
Extracts 22 features from OHLCV (df rows: timestamp, open, high, low, close, volume).

Existing 6 (already proven in Phase 2 — keep naming/behavior):
1. `volatility` — rolling std of returns over `window`
2. `volume_spike` — close volume / rolling mean volume
3. `price_change` — close vs close `lookback` ago (%)
4. `range_pct` — (high - low) / close
5. `volume_ratio_prev` — volume / previous bar volume
6. `rsi` — standard 14-period RSI

New technical 11:
7. `macd_line` — EMA(12) - EMA(26)
8. `macd_signal` — EMA(9) of macd_line
9. `macd_hist` — macd_line - macd_signal
10. `macd_cross` — +1/-1/0 on golden/death cross (sign change of macd_hist)
11. `sma_20` — close / SMA(20) - 1
12. `sma_50` — close / SMA(50) - 1
13. `sma_cross_20_50` — +1 if SMA20 > SMA50, -1 otherwise (regime)
14. `ema_20_50_cross` — +1/-1/0 on EMA20/EMA50 cross
15. `adx` — Wilder ADX(14)
16. `adx_plus_di` — +DI(14)
17. `adx_minus_di` — -DI(14)
18. `atr_pct` — ATR(14) / close

Context 5 (from bar timestamp):
19. `day_of_week` — 0-6
20. `month` — 1-12
21. `ret_1d` — close / previous close - 1
22. `ret_5d` — close / close 5 bars ago - 1
23. `ret_20d` — close / close 20 bars ago - 1

**API:**
- `extract_features(df) -> pd.DataFrame` — one row per bar, NaN for warm-up
- `FEATURE_COLUMNS: list[str]` — canonical ordered list of the 22 names
- `N_FEATURES: int = 22`
- `window` / `lookback` configurable via constants with sane defaults matching Phase 2 (window=20, lookback=10)

**Behavior rules:**
- Never mutate the input df (copy).
- `macd_cross`/`ema_20_50_cross` are lagged sign-of-diff: +1 when diff crosses from ≤0 to >0, -1 reverse, 0 otherwise.
- Use `SimpleMovingAverage`, `ExponentialMovingAverage`, `RSI`, `ADX`, `ATR` from `pandas_ta` if available (check requirements), else hand-rolled pandas versions. Prefer pandas_ta if already a dependency of data_sources.py.

### Step 2 — `feature_store.db` (NEW sqlite DB)
- Reuse `sqlite3` (already used by `outcome_tracker.py`).
- Table `feature_vectors`:
  ```sql
  CREATE TABLE IF NOT EXISTS feature_vectors (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      symbol TEXT NOT NULL,
      timestamp TEXT NOT NULL,
      target INTEGER,            -- NULL until outcome resolves (1 exploded / 0 not)
      features TEXT NOT NULL,    -- JSON array of 22 values, FEATURE_COLUMNS order
      created_at TEXT DEFAULT (datetime('now'))
  );
  CREATE INDEX IF NOT EXISTS idx_fv_symbol_ts ON feature_vectors(symbol, timestamp);
  ```
- `feature_store.py` module (or functions inside feature_pipeline.py) with:
  - `FEATURE_STORE_PATH = "feature_store.db"`
  - `insert_feature_vector(conn, symbol, timestamp, features, target=None)`
  - `load_feature_matrix(conn) -> (X: list[list[float]], y: list[int], meta)` — drops rows with NULL target; returns feature matrix for training
  - `update_target(conn, symbol, timestamp, target)` — called by outcome_tracker on resolution
  - `count_vectors(conn)` for status/debug

### Step 3 — `test_features.py` (NEW)
Custom test framework matching `test_phase2.py` conventions (a `run_tests()` returning (passed, failed, list) — VERIFY by reading test_phase2.py first; do NOT assume pytest).
Cover at minimum 30 assertions:
- Synthetic OHLCV with known shape (e.g. 120 bars, trend + volatility).
- Output row count == input row count; no input mutation.
- Each of the 22 FEATURE_COLUMNS present in output.
- Known-value checks: constant-price series → volatility≈0, price_change≈0, rsi≈50 (verify), atr_pct≈0.
- Monotonic up series → sma_20 > 0, sma_cross_20_50 == +1, adx_plus_di > adx_minus_di.
- Monotonic down series → sma_20 < 0, sma_cross_20_50 == -1, adx_minus_di > adx_plus_di.
- Volume spike series → volume_spike > 1 where engineered.
- NaN warm-up rows exist at head (first ~50 rows may contain NaN) and are dropped by load_feature_matrix.
- DB round-trip: insert → load → same values; update_target works.
- Context features: ret_1d/ret_5d/ret_20d match manual computation on a crafted series; day_of_week/month extracted from timestamp.

### Step 4 — `ml_engine.py` (NEW)
- `MLModelTrainer`:
  - `build_models() -> dict[str, estimator]` — XGBClassifier (n_estimators=100, max_depth=4, learning_rate=0.05, eval_metric='logloss'), RandomForestClassifier (n_estimators=200, max_depth=6, random_state=42), MLPClassifier (hidden_layer_sizes=(64,), max_iter=1000, early_stopping=True)
  - `train(X, y, smote=True) -> dict[str, estimator]` — applies SMOTE (imblearn) if enabled and class imbalance > threshold; fits all 3
  - `save(path, models)` / `load(path)` — joblib
  - `MODEL_PATH = "explosion_model.pkl"` (reuse existing path so old consumers keep working)
- `EnsemblePredictor`:
  - `predict_proba(features: list[float] | np.ndarray) -> float` — soft VotingClassifier with weights [3,2,1]
  - `is_ready()` — True if a model file exists and loads
- `BacktestValidator`:
  - `evaluate(y_true, y_pred, y_prob) -> dict` — accuracy, precision, recall, F1, confusion_matrix
  - `compare_to_phase2(y_true, y_prob, old_scores) -> dict` — lift vs the current weighted-sum
- `classify_signal(prob, dynamic_threshold=True) -> str` — "strong" if prob ≥ high threshold, "medium" if ≥ low, else "weak". Dynamic threshold = percentile-based from recent predictions (kept in a small window).
- Optional: `thresholds_from_predictions(probs, base_high=0.7, base_low=0.5)` helper so dynamic logic is unit-testable without state.

### Step 5 — `train_models.py` (NEW standalone)
- `python train_models.py [--force]`
- Loads matrix from feature_store.db (rows with target). If < 30 rows → warn and exit(1).
- SMOTE (imblearn) unless `--no-smote`.
- Train 3 models, run BacktestValidator (train/test split 80/20, stratified, random_state=42).
- Save ensemble + model metadata (feature names, training date, n_samples, class distribution, metrics) to `explosion_model.pkl`.
- Print summary table (accuracy/precision/recall/F1 per model + ensemble).
- Guard: wrap xgboost import in try/except with clear message telling user to `pip install xgboost imbalanced-learn scikit-learn joblib pandas`.

### Step 6 — `test_ml.py` (NEW)
50+ assertions, same custom framework as step 3:
- build_models returns 3 named estimators; voting classifier weights are [3,2,1].
- train on a synthetic imbalanced dataset (e.g. 200 samples, 10% positive): SMOTE changes class balance; models fit without error; save/load round-trips.
- EnsemblePredictor.predict_proba in [0,1]; monotonic sanity (higher margin → higher prob).
- is_ready False before training artifact, True after.
- BacktestValidator metrics on a crafted perfect classifier (all correct → precision/recall/F1 == 1.0) and a reversed classifier (→ 0.0).
- classify_signal: prob=0.9 → strong, 0.6 → medium, 0.2 → weak (with default static thresholds); dynamic threshold helper returns correct band edges.
- compare_to_phase2 returns lift > 1 when ML prob is better at separating classes (crafted data).

### Step 7 — Modify `predictive_scanner.py`
- Read current file first (predictive_scanner.py:signal scoring).
- Replace the weighted-sum score with:
  ```python
  if EnsemblePredictor.is_ready() and feature_row_valid:
      prob = ensemble.predict_proba(features)
      score = prob * 100
  else:
      score = <existing weighted sum>  # fallback unchanged
  ```
- Fallback MUST be byte-identical behavior to today so Phase 2 tests keep passing.
- Import lazily inside the scoring function (avoid breaking startup if deps missing).
- Keep all existing thresholds/levels intact when fallback is active.

### Step 8 — Modify `signals.py`
- `classify_signal()`: when ML ready → map `prob` → strong/medium/weak via `ml_engine.classify_signal`; else keep existing lift-based logic.
- Signal dict gains optional `"ml_prob"` field when ML used.
- Phase 2 signal tests must still pass (they use the fallback path or assert on fields that don't change).

### Step 9 — `test_integration.py` (NEW)
- End-to-end: synthetic OHLCV → feature_pipeline.extract_features → train tiny model on generated training set → EnsemblePredictor ready → predictive_scanner produces a signal dict → signals.classify_signal returns a string label.
- Assert the full loop returns a valid signal structure and that adding ML path changes the score vs fallback on a crafted explosive series.
- 20+ assertions.

### Step 10 — Run training
- `python train_models.py` against the 400 existing `outcome_tracking` rows.
- Backfill feature_vectors: for each outcome record, re-download/load the symbol history (reuse data_sources) at the outcome's timestamp, extract features, insert with target.
- Check metrics; report accuracy/precision/recall/F1.
- Keep the fallback enabled during a shadow period (log both ML prob and old score) — do not flip the live scanner until metrics look sane (target precision > 0.5, recall > 0.3 on validation).

## Test strategy
- Custom runner matching `test_phase2.py` (verify exact API before writing tests — do not assume pytest).
- After every step, run the full existing suite (`python test_phase2.py` + new file) to guarantee zero regressions.
- New features must never change Phase 2 outcomes when the fallback is active.

## Commit cadence
- Commit after: step 3 (features+store+tests), step 6 (ml+tests), step 9 (integration), step 10 (trained model + README notes).
- 4 commits total. Conventional messages (`feat:`, `test:`).

## Risks / mitigations
- xgboost/imblearn not installed → requirements.txt += `xgboost`, `imbalanced-learn`; guard imports; clear pip message in train_models.py.
- Not enough labeled rows → train_models.py exits with warning; shadow mode keeps fallback until ≥30 labeled rows.
- Feature NaN at warm-up → load_feature_matrix drops NaN rows; scanner only uses ML when the feature row is NaN-free (else fallback).
- Phase 2 behavior drift → every step runs the full existing suite.
